# Permanent cover browsing catalog

`services/library_catalog.py` provides synchronous `index_cover(library_root: Path, key: str) -> dict[str, str]` for a newly committed `<64 lowercase hex>/cover.mp3`, and `rebuild_library(library_root: Path) -> list[dict[str, str]]` for migration/reconciliation. The Lead must explicitly integrate the call **after** the backend publishes the final metadata and MP3, using `await asyncio.to_thread(index_cover, output_dir, actual_key)` in asynchronous code. No backend integration, live migration, or deployment is included here. A catalog failure should be reported rather than invalidate/delete an already committed cover; integration policy belongs to the Lead.

Both calls take `.catalog.lock` with `fcntl.flock` and verify *every* selected committed entry (`status`, directory/key identity, recomputed cache key from stored source/model/index/parameters/instrumental, and SHA-256 of the MP3). `index_cover` deliberately reconciles all committed entries to recover prior interrupted catalog updates. They fail closed on corrupt committed records, symlinked root/ancestors/songs/cache entry/metadata/MP3, preexisting unrelated destination files, or invalid metadata. They do not modify cache directories or request keys, remove views, or rewrite audio. The input root must already exist as an absolute directory. The backend's separate owner lock is **not** acquired; the Lead must ensure committed cache entries are published atomically as currently implemented.

Output is `songs/<artist> - <title> - <voice> - <excerpt> - <accompaniment> - <16-character-key>.mp3`, `README.md`, and `library-index.json`. Filename components are NFKC-normalized, controls/bidi format characters/path separators replaced, and bounded to 240 UTF-8 bytes for the complete basename. On a casefold collision a full key suffix is used, otherwise conflicting unrelated files fail instead of being overwritten. The view uses an **exclusive hardlink** on the same filesystem: no transcoding, extra audio copy, or transient partial MP3; hardlinks consume no additional MP3 data blocks, but chmod/in-place mutation of either name affects both, and cross-filesystem `EXDEV` is an error rather than an implicit copy. Atomic temporary writes with `os.replace` regenerate managed index/README; unrelated files with those names are rejected. Existing hardlinks are checked for matching inode and digest, and re-running unchanged leaves managed text content unchanged.

The public index contains only key, output SHA, sanitized artist/title, voice label, excerpt, accompaniment and relative filename. It never publishes source dictionaries, worker resources, paths, credentials, verified_source, or raw signed URLs. Only model hash `01f2ee572103e0770b896c8a73acce9ed477fcf74d804bb441420c1d8e049319` receives `Natsume Iroha`; other models receive a hash-derived unknown voice label. Local clips use `excerpt_provenance.clip.start_s/end_s` if valid; otherwise a known *clip duration* is shown with **offset unknown**, never a fabricated start or full-song claim. Remote source extent is deliberately `source-extent-unverified`, not an assertion of original/studio/full recording. `instrumental=True` means added backing (`with-backing`), not an instrumental-only recording.

Validation is integrity validation of stored metadata and bytes, **not** an independent MP3 decode, provenance/license verification, a proof against concurrent hostile filesystem mutation, or verification that an upstream source is a complete song. Explicit review and safe migration of the live library remain for the Lead. Tests create only `tmp_path` synthetic cover libraries and never access live output.
