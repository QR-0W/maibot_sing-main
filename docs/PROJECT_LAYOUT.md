# 项目目录与发布清单

遵循 [MaiBot 官方开发规范](https://docs.mai-mai.org/plugin/vibe-coding)。一个项目根统一正式代码、公开文档和开发入口；模型和数据可以不跟踪，且官方不要求其必须与源码物理同目录。以下是组织规范和待执行迁移方案，不代表现存私有资源已搬迁。

```text
maibot-sing/
├── plugin.py / _manifest.json / README.md / LICENSE
├── services/                 # 自有业务代码，随发布交付
├── runtime/                  # 自有受限调度与媒体代码
├── engines/rvc/
│   ├── rvc_infer.py           # 自有正式适配器，跟踪
│   └── upstream/             # 管理员准备的第三方源码，不跟踪/不打包
├── docs/ / tests/             # 公开契约与可复现回归
├── config.example.toml        # 无凭据模板，非运行配置覆盖源
└── .local/                   # 可选的统一本机资料根，整体不跟踪
    ├── models/
    ├── engines/              # 隔离环境等，不代替上面的 sibling upstream 契约
    ├── experiments/
    ├── datasets/
    └── reports-private/
```

## 各层职责

- 正式执行需要的自有代码必须随仓库交付，不依赖维护者的实验路径。实验启动器、临时探测、对照发布脚本不自动成为产品依赖。
- 当前 RVC 接口要求 `rvc_upstream_path == rvc_script.parent / 'upstream'`；配置仓库适配器时使用 `engines/rvc/upstream/`。不能为了目录美观用符号链接绕过资产守卫。
- 第三方源树有明确来源、版本、LICENSE/notices及实际字节记录；隔离环境需要可复现版本约束和安全审查。完整锁及传递依赖许可清单尚未完成，不将历史版本列表冒充锁。
- 模型、索引、离线分离权重、训练材料和声音授权分别记录；私有音频和报告不进入公开仓库。
- SDK 数据目录中的数据库、工作区、长期 covers 和浏览索引是持久运行资产，不能随代码升级删除，也不能混作实验临时目录。管理员现有外置模型仍允许保留，无必要不搬。
- Runner 生成并维护 config.toml；不提交运行配置，不用模板覆盖凭据。不同机器的绝对路径由配置提供。

## 发布排除

`.gitignore` 已排除根 `.local/` 和第三方 upstream。它不能自动排除已经被跟踪的文件，也不能保护手工打包整目录的 ZIP。

发布前用正向清单核对入口、Manifest、所需自有模块/适配器、公开文档及许可材料；审查实际归档成员。数据库及旁路文件、运行配置、Cookie/token、个人日志、模型/音频/数据集、虚拟环境、缓存、私有报告与第三方 checkout 不应进入插件发布包。若发布方法基于 Git，新文件必须在验收后纳入提交，不能遗漏仍未跟踪的正式适配器。

## 迁移前置与回滚

1. 清点每一配置路径、版本、源文件、许可、哈希和所有消费者；区分正式依赖与私有实验。先获得具体迁移许可。
2. 暂停新接纳，确认所有旧 unit、子进程及 offload 已停止或结算；unknown ownership 不能当作已停止。保留共享锁的全局身份，不能给每个新目录另造锁。
3. 冻结计划含绝对 argv、工作区与收据路径；数据库根也已绑定。保留旧路径供旧任务和成品读取，不直接改数据库字符串或热更根路径。
4. 在磁盘和权限满足条件时复制、核对字节/哈希与许可，再在资源门槛内验收新配置；原文件保留为回滚依据。不移动活跃模型或工作区，不自动删除用户音频。
5. 经受信管理入口应用确认后的配置与重载，核对 Supervisor 依赖和实际命令注册；保持 QQ/NapCat 独立。只有新目录通过验证且旧任务引用已妥善处理，才能另行讨论归档旧目录。

当前没有执行此物理迁移。新版 README 将在全部实施与验收结束后从头面向产品撰写，不叙述这次整理过程。
